# 0.4.0の保存先・排他・ID契約

0.4.0は既存mainの保存契約変更を含むため、0.3.0への依存だけを更新するpatchとして配布しない。0.xのminorを分け、0.3系の利用者が明示的に選択して移行する。既存の`^0.3.0`から0.4.0へは自動更新されない。

| 項目 | 0.3.0 | 0.4.0 |
| --- | --- | --- |
| OPFS保存先 | `<root>/turbowarp-plus-projects/<id>/` | `<root>/turbowarp-plus/projects/<id>/` |
| Web Locks名 | `tw-plus-project:<id>` | `turbowarp-plus-browser-project:<id>` |
| ID | 英大小文字・数字・`_`・`-` | 英小文字・数字・`-`、1〜64文字 |

新しい保存先と排他名は、Project Folderのbrowser-projectsと共有するための契約である。exportする`BASE_DIRECTORY`は`turbowarp-plus`、`PROJECTS_DIRECTORY`は`projects`となる。

## 既存データがある場合

この版に自動移行処理は含まれていない。旧保存先を読み取って新保存先へ自動fallbackすることもない。新しい場所へ空の作品を作成しても、旧データが移行されたことにはならない。

0.3系の保存データを使う利用側は、検証済みの移行を用意するまで0.3系の固定を維持する。公開済み0.3.0と対応tagは保持する。

移行を実装する利用側は、次を受け入れ基準とする。

1. 旧版と新版、GUIの同じ作品を扱う全実行経路を停止する。旧版と新版の排他名は異なるため、移行中の同時利用を避ける。
2. 旧保存先の内容全体を退避する。Git管理情報や隠しファイルも含め、ファイルの件数・内容を照合できる状態を残す。
3. 新しいIDを検証する。大文字や`_`を含むIDを単純に小文字化・置換せず、衝突しない対応表と利用側の参照更新を用意する。
4. 新保存先へ移し、全ファイルの内容と作品の読み込み・保存・Git状態・排他を照合する。旧データは検証後も切戻しのため保持する。
5. 実際の対応ブラウザーで再起動と再読込まで確認してから利用側の依存を0.4系へ更新する。

## 切戻し

0.4系で書き込んだ内容は旧保存先へ自動反映されない。依存だけを0.3.0へ戻しても、新版での更新は見えない。新旧の内容を退避・比較し、利用側で逆方向の移行と参照の復元を検証してから戻す。旧保存先や公開版を削除・上書きしない。
